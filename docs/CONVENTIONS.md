# Conventions

## 1. Code style

### Python (pipeline, ml, sensor tests, adapters)
- Python 3.13, managed with **uv** (`uv sync`, `uv run`). Workspace packages: `pipeline`, `ml`, `adapters-budokai`.
- **ruff** for lint and format (line length 100), **mypy --strict** on `pipeline` and `adapters`.
- Pydantic 2 models for every structure that crosses a boundary (log events, `Session`, public JSON). No bare dicts across modules.
- Lambda handlers are thin: parse event → call pure core function → write output. Core has no boto3 imports; I/O goes through small adapter classes injected in handlers.
- No numbers, lists, regexes, copy or thresholds in code: load from `config/` (rule 2). Constants allowed: 0, 1, and protocol facts (e.g. HTTP status codes).
- Logging: structured JSON (`structlog`), never log secrets, raw IPs only inside the ingest step and never at INFO or above.

### TypeScript (web)
- TypeScript strict, ESLint (typescript-eslint, react-hooks, jsx-a11y), Prettier.
- Function components, hooks, Zustand for app state. Three.js code in `web/src/globe/` behind a small React API.
- No user-facing string literals in components (copy from `config/public/copy.json`), no colour literals (tokens only), no emoji (lint + `check-emoji`).
- Icons: only the set chosen in Phase 2 (Solar via Iconify or Lucide) and in-repo SVGs.

### Terraform
- `terraform fmt`, tflint (AWS ruleset), Trivy config scan, Checkov.
- Modules have `variables.tf`, `outputs.tf`, `main.tf`, `versions.tf`, a `README.md` generated by terraform-docs.
- Every resource tagged `project=darb-ki`, `env`, `role` (default_tags).
- Values come from `config/*.yaml` via `yamldecode(file(...))`, not from `.tfvars` with literals.

### Shell
- `set -euo pipefail`, shellcheck clean.

## 3. Testing conventions

- TDD always: failing test first, seen failing, then code (CLAUDE.md §1.8).
- Test names state behaviour: `test_redactor_removes_ipv6_in_wget_argument`, `it("caps a bot burst and shows the remainder count")`.
- Fixtures: sanitised, documentation-range IPs only (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`), `example.invalid` domains, no file content. `make check-private` enforces it.
- AWS: moto only. Terraform: `mock_provider "aws"`. No network in unit tests (pytest-socket `--disable-socket` by default; integration tests enable localhost only).
- Web: Vitest + Testing Library; Playwright + axe for e2e; visual snapshots with a fixed demo seed and reduced motion on.
- Coverage targets (proposed): 90% lines on `pipeline` core and `redact`/`anonymise` (100% branches on those two), 80% on web logic modules. Not on Three.js render code (covered by visual tests).

## 4. Commits

- Imperative, plain English, first line under 72 characters, optional body explaining **why**. Examples:
  - `Reject sensor egress except 443 to S3 prefix list`
  - `Replay keystrokes with recorded timing in session sheet`
  - `Add failing test for IPv6 redaction in URLs` (allowed only if the next commit makes it pass)
- Small and honest: one working step per commit. Many commits are welcome; never fake or backdate.
- **No AI attribution.** "Never add "Co-Authored-By" or any other AI attribution line to commit messages, pull request descriptions, or any other text, in any project. Commit messages end with the last line of the actual description." Never write the word "claude" in a commit message (the push check greps for it). No emoji.
- Author and committer: `Nour Alden Mousa <nmcryptoinvest@gmail.com>` only.

## 5. Branches

- One per phase: `phase/NN-short-name` (see `PLAN.md`).
- Optional short-lived sub-branches inside a phase: `phase/NN-short-name--topic`, merged into the phase branch locally.
- `main` only receives merges approved by Nour.
